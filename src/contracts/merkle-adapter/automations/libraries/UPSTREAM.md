## Native reads and remaining integration code

Aave health uses native `getUserAccountData`. Euler health uses native
`accountLiquidity(account, true)` and normalizes the ratio. Neither wrapper
recalculates protocol collateral portfolios.

The checked Aave Solidity helpers/tests and Euler EVK/periphery do not expose
account-scoped scalar `maxBorrow` getters. Their validation routines access
internal protocol storage. Copying them would not produce an external lens.
The following integration logic therefore remains explicitly local:

- Aave's supported-mode filtering, reserve cash/cap constraints, conservative
  index/base-unit rounding and leaf-pinned minimum health factor. Account data
  and indexes come from the pool; percentage operations use the copied library.
  Protocol rules are in [GenericLogic](https://github.com/aave-dao/aave-v3-origin/blob/8305565ae342f1773c42cd2e4593f175fe5968a0/src/contracts/protocol/libraries/logic/GenericLogic.sol)
  and [ValidationLogic](https://github.com/aave-dao/aave-v3-origin/blob/8305565ae342f1773c42cd2e4593f175fe5968a0/src/contracts/protocol/libraries/logic/ValidationLogic.sol).
- Euler's cash/cap/controller/hook restrictions and bounded amount search using
  the protocol's ask-side debt value. Euler withdrawals call native `maxWithdraw`.

These wrappers are not claimed to be verbatim upstream `maxBorrow` functions.
Protocol failures revert the recipe; accepted leaves independently enforce
health and balance conditions.
